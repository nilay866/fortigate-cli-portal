SYNTAX & PARSER SHIELD

FortiOS CLI Parse & Execution Errors: Exact Causes & Solutions

Every common CLI parsing rejection across FortiOS 6.4, 7.0, 7.2, 7.4, and 7.6 explained.

FortiOS CLI Parser Error Exact Root Cause How to Prevent / Fix in CLI
node_check_object fail! for <field> <name> Missing Object Dependency or Case Mismatch. The address, service, or interface does NOT exist in FortiOS memory yet, or letter casing differs (FortiOS names are strictly CASE-SENSITIVE). Create the address/service object FIRST before referencing it in a policy. Check exact name with get firewall address | grep -i <name>.
command parse error before '...' Unquoted String or Space/Comma Delimiter Error. The name contains spaces or hyphens without quotes, or you used commas to separate multiple ports/services instead of spaces. Enclose names in "double quotes". Separate multiple items with spaces (e.g. set service "HTTP" "HTTPS", NEVER with commas).
attribute set fail for nat Central SNAT Global Conflict. Central SNAT is enabled globally (central-nat: enable). In this mode, configuring NAT inside individual policies is strictly disallowed. Check with get system settings | grep central-nat. If enabled, omit set nat from policy and configure NAT in config firewall central-snat-map.
value parse error before '192.168.1.0/24' Unsupported CIDR Notation. Older FortiOS versions and specific subtrees (like config firewall address) require dotted decimal subnet masks. Always use space-separated dotted decimal: set subnet 192.168.1.0 255.255.255.0. For single host: set subnet <ip> 255.255.255.255.
entry is used by another entry Active Reference Lock. You tried to delete an address or service object that is currently bound to an active firewall policy, VIP, or group. Find the referencing policy with diagnose sys checkused firewall.address.name "<name>", remove it from that policy, then delete.
unknown command before 'utm-status' FortiOS 7.2+ Deprecation. In FortiOS 7.2 and 7.4+, utm-status is deprecated because attaching a security profile automatically activates UTM. Omit set utm-status enable and directly assign your profile: set av-profile "default".
command parse error before 'policy' NGFW Policy-Based Mode. The VDOM is set to Policy-Based NGFW mode instead of Profile-Based mode. In Policy-Based mode, the table name is config firewall security-policy. Verify mode with get system settings | grep policy-mode.
